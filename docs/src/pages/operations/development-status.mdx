# Development status

Whisper's contract, headless SDK, encrypted capsule, and operator orchestration are implemented and verified locally. On Sepolia, the complete vault registration, private bid submission, note discovery, capsule matching, funding acceptance, force reveal, and proof-backed Vickrey settlement path has succeeded against the canonical pool. The system remains experimental and unaudited.

## Repository packages

```text
contracts/  Cairo auction state, private callbacks, hashes, pricing, and tests
sdk/        Bid/capsule composition, commitments, encryption, and shared vectors
operator/   Discovery, note matching, persistence, worker, proving, and relay plumbing
docs/       Vocs site plus the detailed protocol specification
vectors/    Cross-language transcript fixtures
```

## Implemented

### Cairo contract

- token-agnostic auction configuration;
- pool-only `ComputeAndInvoke` submit, accept, settle, and abort paths;
- canonical callback return encoding (`Span<OpenNoteDeposit>` with no trailing values);
- contract-scoped bidder and operator identities;
- submitted-versus-funded bid state;
- accepted note ID uniqueness and ordered bid-set commitment;
- commitment-opening verification;
- deterministic Vickrey pricing and tie-breaking; and
- terminal settlement and abort state.

### TypeScript SDK

- Cairo-compatible request encoders and hashes;
- bid transcript and operator-action builders;
- authenticated reveal capsules using ECDH, HKDF-SHA256, and AES-256-GCM;
- refund, proceeds, and winner routing commitments; and
- shared Cairo/TypeScript test vectors.

### Operator

- idempotent capsule upload and public configuration API;
- SQLite WAL persistence with five-second busy timeout;
- Whisper event scanning and durable block cursor;
- pool receipt `EncNoteCreated` extraction;
- vault note discovery and transaction-scoped intersection;
- retryable discovery lag and exact authenticated-amount note matching;
- bid/capsule/note validation;
- private bid acceptance and Vickrey settlement planning;
- stale work-lease recovery and deadline scheduling;
- official Privacy SDK composition boundary;
- proof-backed outside-execution relaying; and
- startup validation without automatic onchain actions.

## External integration boundary

The operator dynamically loads `@starkware-libs/starknet-privacy-sdk@0.14.3-rc.5`, which is distributed through GitHub Packages. Local registry authentication is required before it can be installed and exercised directly.

Copy the provided registry template and supply the token only in your local environment:

```sh
cd operator
cp .npmrc.example .npmrc
export GITHUB_PACKAGES_TOKEN="..."
pnpm add @starkware-libs/starknet-privacy-sdk@0.14.3-rc.5
```

Do not commit `.npmrc` or send the token to another service. The repository ignores the local file.

## Live Sepolia status

The repository records the disposable vault, relayer, corrected Whisper deployment, and successful auction-2 smoke transactions in `deployments/sepolia.json`. The public StarkWare prover and direct pool-contract discovery are sufficient for Sepolia testing; secrets and bid openings remain in owner-only files outside the repository.

One additional operational requirement was confirmed live: a callback-only operator proof is rejected by the pool as `NO_REPLAY_PROTECTION`. Acceptance succeeded when the same batch consumed and reissued a separate vault-owned note, creating a nullifier while leaving the escrowed bid note untouched. After the force-reveal deadline, settlement consumed the accepted 0.2 STRK note and privately reissued 0.1 STRK of winner change plus 0.1 STRK of seller proceeds. Production automation needs a durable replay-note inventory and rotation policy.

## First live test

The smallest meaningful integration exercise is:

1. Validate the configured chain, pool, Whisper deployment, and public keys.
2. Register the service-owned vault through the explicit registration action.
3. Shield a small amount in a separate transaction and wait for the note to mature.
4. Submit one exact-value private bid note and Whisper callback in the same batch.
5. Verify event scanning, note discovery, authenticated-amount correlation, capsule validation, and funding acceptance. Include a separate replay-protection note in the acceptance batch.
6. Advance into the force-reveal window and settle.
7. Discover the loser/winner/seller output notes and reconcile their amounts.

No mainnet registration or transaction should happen implicitly at process startup. Registration, deployment, and live transactions are separate operator actions.

Use the official [SDK setup requirements](https://strk20-by-example.org/sdk/setup-requirements), [registration](https://strk20-by-example.org/sdk/register), [note discovery](https://strk20-by-example.org/sdk/note-discovery), and [multi-operation batch](https://strk20-by-example.org/sdk/multi-op-batch) guides during this test.

## Before meaningful funds

- repeat the verified lifecycle on mainnet with disposable low-value accounts;
- define key backup, rotation, and incident procedures;
- add request authentication and rate limits to capsule upload;
- add worker alerts before `abort_after`;
- back up and test recovery of the operator database;
- obtain independent Cairo and cryptographic review; and
- document the custodial risk in every bidder-facing integration.
