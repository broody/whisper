# Development status

Whisper's contract, headless SDK, encrypted capsule, and operator orchestration are implemented and verified locally. The current standard transfer + invoke bidder architecture has also completed the full Sepolia lifecycle against the canonical pool using the official Privacy SDK: private bid submission, discovery, acceptance, force reveal, and settlement. The interactive Ready Wallet handoff and additive top-up path still need live testing. The system remains experimental and unaudited.

## Implemented

- pool-only standard `privacy_invoke` submission and top-up paths;
- operator-only `ComputeAndInvoke` accept, settle, and abort paths;
- canonical callback return encoding (`Span<OpenNoteDeposit>` with no trailing values);
- random-nonce bid groups and contract-scoped operator identity;
- submitted-versus-funded bid state;
- accepted note ID uniqueness and ordered bid-set commitment;
- commitment-opening verification;
- additive tranche aggregation, combined group refunds/change, deterministic Vickrey pricing and tie-breaking; and
- terminal settlement and abort state;
- OpenZeppelin upgradeability guarded by two-step ownership; and
- unified offchain/ERC-20/ERC-721/ERC-1155 fulfillment with committed winner claims and terminal returns.

### TypeScript SDK

- Cairo-compatible request encoders and hashes;
- Wallet API transfer + invoke builders for initial bids and top-ups;
- operator `ComputeAndInvoke` action builders;
- authenticated reveal capsules using ECDH, HKDF-SHA256, and AES-256-GCM;
- refund, proceeds, and winner routing commitments; and
- shared Cairo/TypeScript test vectors; and
- unified fulfillment encoders plus winner-claim commitment helpers.

### Operator

## External integration boundary

The operator dynamically loads `@starkware-libs/starknet-privacy-sdk@0.14.3-rc.5`, which is distributed through GitHub Packages. Local registry authentication is required before it can be installed and exercised directly.

Copy the provided registry template and supply the token only in your local environment:

```sh
cd operator
cp .npmrc.example .npmrc
export GITHUB_PACKAGES_TOKEN="..."
pnpm add @starkware-libs/starknet-privacy-sdk@0.14.3-rc.5
```

Do not commit `.npmrc` or send the token to another service. The repository ignores the local file.

## Live Sepolia status

The repository records the disposable vault, relayer, active v0.4 Whisper deployment, prior deployments, and successful smoke transactions in `deployments/sepolia.json`. The active event-indexing build was declared from commit `dd8b61a` and uniquely deployed through Starknet's Universal Deployer Contract at `0x02ca43bf2b1e68ae9f39a43e36fce239097444985b4b774b06d0f628a4d678c4`. It embeds OpenZeppelin upgradeability and two-step ownership, with the disposable relayer as the current upgrade owner. Its class hash, canonical pool address, and owner have been verified onchain. Auction 1 completed private bid submission, replay-protected acceptance, force reveal, and settlement. The emitted `AuctionCreated`, `BidSubmitted`, `BidFunded`, `BidRevealed`, and `AuctionSettled` records provide a complete Torii-indexable history: one submission, one funded bid, a 0.1 STRK winning bid, no second bid, and a 0.05 STRK clearing price.

The active smoke used `sncast` for public approval, auction creation, receipt checks, and contract readback. The official Privacy SDK built and proved the private standard transfer + invoke bid plus the operator-only acceptance and settlement batches; this is Wallet API-compatible action semantics, not a Ready interactive-wallet test. On the prior v0.4 deployment, Auction 2 completed the same lifecycle. Its first smoke auction intentionally remained unfunded after transaction-scoped discovery found two notes matching the committed amount; the operator rejected the ambiguous match instead of guessing a note ID. The previous v0.3 deployment's offchain settlement, Stake Wars reader verification, and ERC-20 escrow/reclaim smoke remain preserved as historical evidence in the deployment metadata.

Two operational requirements were reconfirmed live. First, the relayer submitting an outside-execution proof must approve the pool to collect its public privacy fee. Second, a callback-only operator proof is rejected by the pool as `NO_REPLAY_PROTECTION`. Acceptance succeeded when the same batch consumed and reissued a separate vault-owned note, creating a nullifier while leaving the escrowed bid note untouched. After the force-reveal deadline, settlement consumed the accepted 0.1 STRK note and privately reissued 0.05 STRK of winner change plus 0.05 STRK of seller proceeds. Production automation still needs relayer fee monitoring plus a durable replay-note inventory and rotation policy.

## First live test

The smallest meaningful integration exercise is:

1. Validate the configured chain, pool, Whisper deployment, and public keys.
2. Register the service-owned vault through the explicit registration action.
3. Shield a small amount in a separate transaction and wait for the note to mature.
4. Connect Ready, build the Wallet API `transfer` + `invoke` action array, and submit it with `strk20InvokeTransaction(actions)`.
5. Verify event scanning, note discovery, authenticated-amount correlation, capsule validation, and funding acceptance. Include a separate replay-protection note in the acceptance batch.
6. Submit a second tranche for the same group and confirm both are funded.
7. Advance into the force-reveal window and settle; verify that the two tranche amounts are aggregated before pricing.
8. Discover the loser/winner/seller output notes and reconcile their amounts.

No mainnet registration or transaction should happen implicitly at process startup. Registration, deployment, and live transactions are separate operator actions.

Use the [Wallet API overview](https://strk20-by-example.org/starknet-wallet-api/overview) and [private DeFi composition guide](https://strk20-by-example.org/starknet-wallet-api/private-defi) for the bidder, then the official [SDK setup requirements](https://strk20-by-example.org/sdk/setup-requirements), [note discovery](https://strk20-by-example.org/sdk/note-discovery), and [multi-operation batch](https://strk20-by-example.org/sdk/multi-op-batch) guides for the operator.
